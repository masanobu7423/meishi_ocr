## 0. 見方（オブジェクトで分ける）

前回までで「名刺（人）」「会社」「出力」は揃った。今回の対象は**「接点」**（いつ、誰と連絡したか）。

| オブジェクト | 状態 | 足りないこと |
|---|---|---|
| 接点（連絡した事実） | どこにも残らない。「連絡済み」は次回連絡日を消すだけ | 最後に連絡した日、次の予定 |
| 連絡予定 | ホームは件数だけ。一覧で探して、開いて、電話する | ホームで相手が見えて、その場で電話できること |
| 連絡済み | 一覧タブの選択バーだけ。日付は消えるだけ | 次の予定をその場で入れること、検索・ホームでも使えること |

## 1. 競合他社の視点から見た問題点（3 つ）と解決策（1 つ）

1. **接点の履歴が残らない。** Sansan は「接点」、Eight はやり取りの記録を持つ。当アプリは「連絡済み」を押すと次回連絡日が消えるだけで、連絡した事実がどこにも残らない。
2. **ご無沙汰の相手を見つけられない。** 営業向けの名刺管理は「しばらく接点のない相手」を出して掘り起こしを促す。建設業でも、協力会社との定期的な連絡は関係維持の基本だが、当アプリでは探せない。
3. **外での分析に「関係の新しさ」が出ない。** CSV（Excel）、Obsidian のノート、電話帳のメモのどれにも最終接触日がなく、関係の濃さを集計できない。

**解決策（1 つ）: 項目「最終連絡日」（`lastContact`）を足し、接点を記録する。**
- 「連絡済み」で今日の日付が入る。確認画面でも日付を選んで直せる。
- 検索（台帳）に「ご無沙汰（90 日以上）」の絞り込みを足す。基準日は最終連絡日、なければ取込日。
- CSV の列、ノートの `last_contact`、電話帳のメモ「最終連絡:」に出す。行にも「最終連絡 MM/DD」を出す。

## 2. 利用者の視点で不便なこと（3 つ）と解決策（1 つ）

1. **連絡予定の相手に、ホームから直接かけられない。** 件数タイル → 一覧 → 電話の 2 段かかる。
2. **「連絡済み」にしても次の予定が入らない。** 「また 1 か月後に」と思っても、名刺を開いて日付を選び、保存し直す必要がある。
3. **「連絡済み」が一覧タブにしかない。** 検索（台帳）で電話した後は、タブを移って探し直す必要がある。

**解決策（1 つ）: 連絡の一連の流れ（見る → 電話 → 済み → 次の予定）をその場で終えられるようにする。**
- ホームの件数タイルの下に、連絡予定の近い順 3 件を電話ボタン付きで並べる。
- 「連絡済み」を押すと「次の予定」を選ぶシートを出す（なし / 1 週間後 / 2 週間後 / 1 か月後 / 3 か月後）。月の計算は月末で丸める（1/31 の 1 か月後 = 2/28）。
- 「連絡済み」は一覧・検索・ホームのすべての選択バーで使えるようにする。

## 4. やらないこと

- **電話ボタンを押しただけで最終連絡日を入れること**: つながったかどうかが分からない。記録は利用者の「連絡済み」で行う。
- **接点ごとの履歴（日付とメモの一覧）**: 保存形式にリストが要る。最終連絡日とメモで足りないという声が出てから。
- **「連絡済み」で電話帳のメモを即時更新すること**: 前回と同じく、その名刺を次に保存したときに反映する。
