# 名刺スキャン 総合評価と S+ への計画（2026-11-02）

対象: HEAD 3cdecc5（テスト 298 件、全通過、CI 成功）。製品版は v0.2.9 (12)、内部テストは v0.2.14 (17)。
評価は忖度なしで付ける。根拠は、計測した数字・テスト・実機での確認の 3 つだけにする。実機で確かめていない機能は、コードとテストが揃っていても A を上限にする。

## 1. 評価の尺度

| 評価 | 意味 |
|---|---|
| S+ | 競合（Eight・Sansan・CamCard）と並ぶか上回る。自動テストと実機の両方で裏付けがある |
| S | 競合と並ぶ。裏付けはあるが、1 つ弱いところがある |
| A | 作りとテストは揃っている。実機の確認か規模の検証が足りない |
| B | 動くが、既知の欠陥か大きな未検証がある |
| C | 利用者や公開に実害が出得る欠陥がある |

## 3. 競合他社の視点から見た問題点（3 つ）と解決策（1 つ）

1. **信頼の土台で負ける。** Eight・Sansan は法人の監査に耐えるプライバシーポリシーとセキュリティの説明を持つ。当アプリのポリシーは実際の動作より狭く書かれていて、それ自体が規約上のリスクになっている。
2. **出荷の確かさで負ける。** 競合は段階的な配信とクラッシュの監視で、変更を小さく出す。当アプリは、確かめていない 9 回分の変更を一度に製品版へ出そうとしている。
3. **精度の主張に根拠が足りない。** 競合は精度を数字で示す（手入力による保証）。当アプリの数字は 28 枚の標本で、建設業の項目は各 1 枚しかない。

**解決策（1 つ）: 「出荷の門」を決め、通ったものだけを製品版にする。** 門は次の 5 つ。
- ① ポリシーが実際の動作と一致していること
- ② 既知のデータ不具合が 0 件であること
- ③ 実機の確認表がすべて埋まっていること
- ④ golden が 60 枚以上あり、氏名・会社・住所が 95% 以上であること
- ⑤ 段階的な配信（20% → 100%）と、Android vitals の確認

## 4. 利用者の視点で不便なこと（3 つ）と解決策（1 つ）

1. **新しい機能が製品版に届かない。** 台帳・接点・要確認・まとめる・ゴミ箱は、製品版の利用者にはまだ見えない。
2. **機能が増えて、どこに何があるか分からない。** 使い方の案内がアプリ内にもストアにもない。メニューのシートには説明を付けたが、全体像は分からない。
3. **電話帳から取り込んだ住所が欠ける**（既知の不具合）。

**解決策（1 つ）: 「直してから、小さく、説明付きで届ける」。**
- 不具合（R0）とポリシーを直した版を、製品版 v0.3.0 として段階配信する。
- ストアの説明文とスクリーンショットを、台帳・連絡予定・要確認の 3 つを軸に作り直す。
- アプリの初回起動とアップデート後に「新しくできること」を 1 枚だけ出す（閉じたら二度と出ない）。

## 10. 決定 1・2 の実装（2026-11-02、推奨案、利用者の承認による）

- 決定 1: `android/app/src/release/AndroidManifest.xml` で、リリース版だけ `INTERNET` を外した（`tools:node="remove"`）。debug と profile は Flutter の開発ツールのために残す。`ACCESS_NETWORK_STATE` は残す（送信部品がネットワーク条件付きのジョブを予約するのに要る。これ自体はデータを持たない）。
- 決定 2: `res/xml/data_extraction_rules.xml`（Android 12 以降）で、クラウドへのバックアップから全領域を除外し、端末間の直接転送は全領域を許可した。`res/xml/backup_rules.xml`（Android 11 以前）は、クラウドと転送の区別がないので全領域を除外した。
- 実機（P08_T、リリース版をローカルの debug 鍵で署名し直したもの）で確認した。
  - 要求する権限に `INTERNET` がない。
  - 起動・まとめて取込（OCR）が正常に動く。氏名・会社・電話・携帯・メール・郵便番号を読めた。
  - ML Kit の送信ジョブを強制的に実行すると、`TransportRuntime.Executor: SecurityException: Permission denied (missing INTERNET permission?)` で送信に失敗する。部品自身がこの例外を受け止めるので、アプリは落ちない（プロセスはそのまま、crash バッファは空）。
- 確認していないこと: ドキュメントスキャナー（Play 開発者サービス側の画面）をリリース版で開くこと、Android 12 以降での端末間の転送。
- ポリシー: このビルドが製品版に行き渡るまでは、今の製品版が送信するので、公開中の記述（§1 の診断情報、§7 のネットワーク、§8 の Android のバックアップ）は残す。行き渡ったら、この 3 か所を「送らない／クラウドには保存しない／機種変更の直接転送では引き継ぐ」に改める。
- データ セーフティ: 送信しない版が製品版になった後も、古い版が残る間の申告をどうするかは利用者が判断する。

- 2026-11-03: データ セーフティを、製品版の動作（ML Kit の診断情報とデバイス ID を「収集する」）に合わせて直し、保存した（`docs/store/data-safety.md`）。審査への送信は利用者。送信後、領域 7 は B から A に上げる。
