# meishi_ocr — Phase 0 スパイク

端末内（オフライン）で動く日本語名刺 OCR アプリの Go / No-Go 判定用スパイク。
「Flutter + ML Kit で作る価値が iOS Live Text / Google レンズに対してあるか」を測るための
使い捨てコードであり、製品コードではない。

## 構成

| パス | 役割 |
|---|---|
| `lib/ocr/ocr_line.dart` | ML Kit `TextLine` の必要部分（文字列 + 矩形）。JSON 往復可 |
| `lib/ocr/extractor.dart` | 純 Dart の項目抽出器（パターン → キーワード → 最大文字高さ = 氏名）。縦書き判定 `isVertical`、必須項目欠落 `missingCore` も同居 |
| `lib/main.dart` | 1 画面: 表裏撮影 → OCR → 項目レビュー（OCR 行チップをタップして項目へ割当） → golden JSON 保存。inbox 一括取込あり |
| `test/golden_test.dart` | 精度計測ハーネス。`test/golden/*.json` の項目別ヒット率を表で出力 |
| `test/golden/0xx_*.json` | 合成フィクスチャ。`strict: true` で完全一致を要求（抽出器の回帰テスト） |
| `test/golden/1xx_*.json` | 実機 OCR ダンプ（合成名刺のクリーン描画）。`strict: false`、精度表のみに寄与 |
| `test/golden/2xx_*.json` | 実機 OCR ダンプ（写真風に劣化させた描画: 台形歪み・ぼかし・ノイズ・影） |
| `lib/ocr/card_note.dart` | 名刺 1 枚 → Obsidian MD（frontmatter + `#タグ` + `[[リンク]]`）。`test/card_note_test.dart` が形式を固定 |
| `android/app/proguard-rules.pro` | 未同梱スクリプト（中国語・デーヴァナーガリー・韓国語）の `-dontwarn`。リリースビルドに必須 |

## Phase 0 の手順

1. Android 実機で `flutter run`（iOS は Mac で `pod install` が先に必要）。
2. 実名刺 30 枚程度（縦書き・横書き・英語裏面・デザイン名刺を混ぜる）について、
   **表を撮影** → 必要なら **裏を撮影** → 画面で項目を修正（チップをタップで割当）→ **JSON保存**。
   撮影ボタン長押しでギャラリーから選択。
3. JSON を取り出す（Android は外部ストレージのアプリ領域に出るので `run-as` 不要）:
   ```bash
   MSYS_NO_PATHCONV=1 adb pull /sdcard/Android/data/jp.tobishoku.meishi_ocr/files/golden ./pulled
   ```
4. 各 JSON の `expected` を目視で確定し（名刺に無い項目は `null`）、`NNN_<メモ>.json` に改名して
   `test/golden/` へ。`strict` は `false` のまま。
5. `flutter test` で精度表が出る。判定基準:
   - 氏名 80 % 以上かつ電話・メール 95 % 以上 → Phase 1 へ
   - 氏名 60〜80 % → レイアウト解析を改善して再計測
   - 氏名 60 % 未満 → 中止（Live Text で足りる）
6. 同じ 30 枚を iOS Live Text（カメラ → テキスト選択 → 連絡先に追加）に通し、氏名・会社が使える形で
   出たかを 1 枚ずつ記録。差が出なければ中止。

### 一括取込（ピッカー不要）

アプリバーのフォルダアイコンは `<外部領域>/inbox` の画像をすべて表面として OCR し、
1 枚 1 JSON を `golden/` に書く（`expected` には抽出器の推定値が入る）。
inbox フォルダは**アプリに作らせる**（最初に一度アイコンを押す）。`adb shell mkdir` で作った
フォルダは Android 11 以降アプリから読めない。

```bash
export MSYS_NO_PATHCONV=1   # Git Bash が /sdcard を Windows パスに変換するのを防ぐ
adb push card.jpg /sdcard/Android/data/jp.tobishoku.meishi_ocr/files/inbox/
# フォルダアイコンをタップ → 完了後
adb pull /sdcard/Android/data/jp.tobishoku.meishi_ocr/files/golden ./pulled
```

## 電話帳登録（`lib/ocr/contact_mapper.dart`）

**電話帳に登録** は flutter_contacts 2.x で端末の連絡先に書く。レビュー画面で修正した値をそのまま使う。

- 氏名は「姓 名」で分割。ふりがなは名刺のかな行をカタカナ化、無ければローマ字行から変換
  （`lib/ocr/romaji.dart`、ヘボン式 + 訓令式の一部。長音は推定しない: `Taro` → `タロ`）。
- 電話 = 勤務先、携帯 = 携帯、FAX = 勤務先 FAX のラベル付き。会社・部署・役職は組織欄、住所は勤務先住所、
  メモに `名刺取込 <日付> (<golden JSON 名>)`。
- **重複検知**は電話番号（数字のみ比較、`+81` は `0` に畳む）とメール（大文字小文字無視）の完全一致のみ。
  名前では判定しない（別人の田中さんを統合する方が被害が大きい）。
- **類似登録があるとき**（`lib/duplicate_screen.dart`, `lib/ocr/merge.dart`）は既存の連絡先と名刺を項目ごとに並べる。
  同じ項目は「（同じ）」1 行。違う項目はカードになり、**「名刺の値を使う」**のチェックで採用を決める
  （既定は既存のまま。既存が空の項目だけ最初からチェック）。電話・携帯・FAX・メール・URL・住所のような複数値を
  持てる項目は、チェック後に**「既存の値も残す」**（既定オン）が出て、両方残すか名刺だけにするかを選べる。
  各カードの末尾に**「統合後: …」**のプレビューが出るので、結果を見てから「選んだ内容で再登録」を押す。
  「すべて名刺の値にする / すべて既存のままにする」で一括切替。
  他の操作: **別人として登録**、**既存を電話帳アプリで編集**（端末標準の編集画面）、**既存を削除して名刺で登録**
  （元に戻せないので確認ダイアログ）。統合後は SnackBar の**「元に戻す」**で統合前の内容に書き戻せる（8 秒間）。
  実機で統合（連絡先 1 件のまま電話 3 件）と削除→再登録（id が変わる）を確認済み。
- 権限: Android `READ_CONTACTS` / `WRITE_CONTACTS`、iOS `NSContactsUsageDescription`。
  iOS のメモ欄は Apple の entitlement が別途必要（未対応）。

実機確認（P08 T）: 写真風名刺 → OCR → 登録で、姓名分割・ふりがな `ヤマダタロウ`・電話 3 件のラベル・メール・
住所・組織・URL・メモが連絡先 DB に入ることを `adb shell content query` で確認済み。テスト用連絡先は削除済み。

## リリース（内部テスト）

- バージョンは `pubspec.yaml` の `version: <name>+<code>`。v0.2.0 (2) から Play 内部テスト用。
- **Android AAB**: `flutter build appbundle --release`。署名は `android/key.properties`（git 外）が指す
  `android/app/upload-keystore.jks`（git 外）。この 2 ファイルは必ずバックアップし、失くすと同じアプリとして更新できない。

  事前に App Store Connect でアプリと bundle id を作り、API キーを Codemagic に登録する。
- リリース名とノート（JA/EN）は `docs/releases/v<version>.md`。
- プライバシーポリシーは `docs/privacy.md`（公開 URL: https://masanobu7423.github.io/meishi_ocr/privacy.html 、GitHub Pages が `docs/` を配信）。`python tool/privacy_html.py` で `docs/privacy.html` を再生成。
- `git tag v0.2.0 && git push --tags` で GitHub Actions が APK（debug 鍵）を artifact に置く（配布用ではなく動作確認用）。

## 画面構成（`lib/app_shell.dart`）

下部タブ 4 つ。ホーム / スキャン / 検索 / 一覧。データは vault のノートから読み、スキャンで保存すると他タブが更新される。

| タブ | ファイル | 内容 |
|---|---|---|
| ホーム | `lib/home_screen.dart` | 保存枚数・今月の枚数、名刺を撮影 / アルバムから / まとめて取込、最近の 5 枚（タップでスキャン画面に開く）、すべて見る |
| スキャン | `lib/main.dart` | 下記の確認画面。他タブから名刺を開くとここに表示される |
| 検索 | `lib/card_list.dart` `SearchScreen` | 氏名・会社・役職・メモで絞り込み（大小・全角半角・かな種別を無視） |
| 一覧 | `lib/card_list.dart` `ListScreen` | 新しい順 / 会社順 / 氏名順の切替 |

vCard 書き出しとバックアップは右上メニュー。`test/card_list_test.dart` と `test/home_screen_test.dart` が並び順・絞り込み・ホームの集計を固定。

## スキャン画面（`lib/main.dart` + `lib/card_form.dart` + `lib/theme.dart`）

設計の約束は `DESIGN.md`（対象者・トーン・トークン・文言規則）。状態は 2 つ。

- **空状態**: 「名刺を撮影するか、アルバムから選んでください」と大きな 2 ボタン。通信を使わない旨を 1 行。
- **確認状態**: 上に名刺写真（表、裏は未撮影なら撮影/アルバムボタン）、一括取込中は「2/6 枚目を確認中」と前後ボタン。
  その下に日本語ラベルの項目（氏名・ふりがな・会社・部署・役職・電話・携帯・メール・郵便番号・住所・FAX・URL・ローマ字）。
  読み取れなかった必須項目には「読み取れませんでした。下の文字をタップするか入力してください」。
  最後に「読み取った文字」のチップ。最後に触った欄が入力先で、欄に鉛筆アイコンが付く。
- **固定の操作バー**: 次の名刺を撮影 / 保存 / 電話帳に登録。登録後は SnackBar「電話帳に登録しました」、
  一括取込中なら自動で次の名刺へ。エラーは画面上部のバナーに「起きたこと + 直し方」。
- 開発用語（JSON / golden / inbox / スパイク）と英語のフィールドキーは画面に出さない。
- `test/card_form_test.dart`: 日本語ラベル、チップ→入力先、欠落ヘルパー、文字サイズ 2 倍での崩れなしを固定。

## Google の連絡先との同期（`lib/ocr/sync.dart`）

自前の通信は一切しない。Android は連絡先を **Google アカウント側に作れば OS が自動で Google と同期する**ので、
アプリがやるのは次の 2 つだけ。

- **登録先のアカウント**（メニュー / ホームの「登録先」行）: 端末のアカウント一覧から選ぶ。既定は最初の Google
  アカウント、無ければ端末の既定（同期されない）。選択は `settings.json` に保存し、以後の登録（通常・別人・置換）で使う。
- **未登録の名刺を電話帳に登録**（メニュー）: 保存済みの全名刺のうち、電話かメールが一致する連絡先が無いものだけを
  選んだアカウントに作成する。件数（登録 / 既存 / 氏名なし）を確認ダイアログで出してから実行。

People API は使わない（OAuth・通信・審査が要り、「通信を使わない」約束に反する）。iOS は iCloud 連絡先が同じ役割。

## 確認画面からの移動と写真の拡大（`lib/ocr/actions.dart`）

名刺を開いた確認画面の写真の下に、電話・携帯・メール・ウェブ・地図のチップが出る（値がある項目だけ）。
タップで `tel:` / `mailto:` / `https://` / `geo:0,0?q=住所` を端末のアプリに渡す（`url_launcher`）。
名刺の写真はタップで全画面・ピンチ拡大。Android 11 以降の package visibility のため、`AndroidManifest.xml` に
`<queries>` を宣言している。

## 履歴・メモ・バックアップ・ダークモード

- **履歴**（時計アイコン、`lib/history_screen.dart`）: 保存した名刺を新しい順に一覧し、氏名・会社・役職・メモで検索
  （大文字小文字・全角半角・ひらがなカタカナを区別しない）。タップで確認画面に戻し、保存した値と写真をそのまま再表示。
  一覧は vault のノートの frontmatter だけから作る（`lib/ocr/history.dart`）ので、Obsidian で直した内容も反映される。
- **メモ**: 「メモ（会った場所・日付など）」欄。ノートの frontmatter `memo` と本文、連絡先のメモ欄の先頭に入る。
  履歴の検索対象。OCR からは決して埋めない。
- **バックアップ**（メニュー）: `backup/meishi_backup_<日付>_<時刻>.zip` に vault（ノート + 画像）・golden・learned.json を
  まとめる。
- **復元**（メニュー「バックアップから復元」、`CardStore.restore`）: `backup/` にある zip を選んで取り込む。同じ名刺（同じ
  `golden/<stem>.json`）は上書き、ほかは残す。`learned.json` は端末に無いときだけ入れる。zip 内の `vault/`・`golden/`・
  `learned.json` 以外（`..` を含むパスも）は無視する。書けなかったファイルは数えて `log/errors.txt` に残し、残りは続ける。
  別端末へは、zip を Files アプリや adb で `backup/` にコピーしてから復元。JSON の `images` パスは `images/` 配下だけを
  信用する（他所の zip に細工があっても領域外を消さない）。
- **削除**（確認画面のゴミ箱、`CardStore.deleteCard`）: 保存済みの名刺を開いているときだけ出る。読み取り結果・ノート・写真を
  消し、一覧を更新する。電話帳の連絡先は消さない。
- **再保存**: 保存済みの名刺を直して保存すると、ノートを作り直して古いノートを消し、`scanned` の日付は最初の保存日を保つ
  （以前は日付違いのノートが増えて一覧に二重に出ていた）。
- **ダークモード**: 端末設定に追従（`darkTheme`）。

## 手動修正から学ぶ（`lib/ocr/learned.dart`）

「機械学習で今後の解析に応用」は、この規模（数十〜数百枚、端末内、無料）では**モデルの再学習ではなく、修正から
ルールを増やす**のが唯一効く方法。ML Kit のモデルは学習できず、自前モデルは数千枚の正解データと学習基盤が要る。
忖度なしに言うと、それを「ML」と呼ぶかは言葉の問題で、やることは次の 3 つ。

| 学習するもの | きっかけ | 次回の効き方 |
|---|---|---|
| 行 → 項目の記憶 | OCR 行をチップで別の項目に入れて保存した | 同じ行文字列（同じ会社名・部署・役職）が来たら、ヒューリスティックより先にその項目へ |
| 役職・部署の語彙 | 組込みの語彙にない 1 語を役職/部署に入れた（例: フェロー） | 組込み正規表現に OR される |
| 文字の誤読ペア | 1 文字だけ直した修正（健ニ → 健二）が **2 回以上** | 氏名・会社名に置換を適用（1 回では適用しない） |

- 保存のたびに「抽出器の推定」と「保存した値」の差分を `log/corrections.jsonl` に残し、`learned.json` を更新する。
  状態行に「修正を学習しました」と出る。
- 修正済みの golden JSON はそのまま回帰テストの正解になる。`test/golden/` にコピーして `flutter test` を回せば、
  ルールの効果と副作用が数字で見える（これが運用レベルでの「学習ループ」）。
- 実機確認: k01 で OCR 行「営業部 部長」を title に入れて保存 → `learned.json` に記憶され、再取込で title が
  「営業部 部長」として自動抽出された。
- 上限: 誤読ペアは文字単位の全置換なので、誤った対を学習すると広く効く。2 回ルールで緩和しているが、
  実名刺で誤爆したら対象を漢字のみに絞る（コードにその旨の `ponytail:` コメント）。

## 名刺画像の保存（表・裏）

保存のたびに撮影画像を `vault/images/<stem>_front.jpg` / `<stem>_back.jpg` にコピーする（カメラの一時ファイルは
消えるため）。golden JSON には `images: {front, back}`、ノートには frontmatter `image_front` / `image_back` と
Obsidian の埋め込み `![[images/<stem>_front.jpg]]` が入るので、vault を Obsidian で開くとノートに名刺の写真が表示される。
一括取込では inbox の元画像が表面としてコピーされる。

「DB」は SQLite ではなく、この `golden/`（JSON）+ `vault/`（MD + 画像）のファイル群。1 名刺 = 1 JSON + 1 MD + 画像で、
全文検索・集計は Obsidian 側（`_名刺一覧.md`、タグ、バックリンク）に任せる。件数が数千を超えて一覧生成が遅くなったら
SQLite 索引を足す（現状は YAGNI）。

**裏面の OCR は日本語モデルに統一した。** 以前は裏面を英語モデルで読んでいたため、日本語の裏面（地図・事業内容）で
「裏: 0 行認識」になる事象が実機で出た。日本語モデルは英字も読めるので、英語モデルは使わない。

## 斜め撮影の補正（`lib/ocr/ocr_pipeline.dart`, `lib/ocr/deskew.dart`）

2 段構えにした。

1. **撮影時の台形補正（Android）**: 「表を撮影 / 裏を撮影」は ML Kit 文書スキャナ（端末内・無料・Play 開発者サービス経由）を
   開く。辺の自動検出と透視変換で名刺を正面から見た長方形に直してから JPEG を返すので、「少し斜めから撮った」歪みは
   ここで消える。スキャナが使えない端末や iOS は、従来の枠付き自前カメラにフォールバック。
2. **OCR 後の回転補正（全プラットフォーム）**: 1 回目の OCR で ML Kit が返す各行の角度（iOS は corner points から算出）の
   中央値を傾きとみなし、1.5° 以上なら `image` パッケージで水平に回して 2 回目の OCR を行う。読めた文字数が減らない方を採用し、
   `log/deskew.txt` に `tilt=-19.9 chars 156->156 levelled` のように記録する。golden JSON には 1 回目の行も `frontRaw` で残すので、
   補正の前後を同じ採点で比べられる（`test/golden/3xx_*_raw.json` / `_deskewed.json`）。

FastaLife の `OcrService` から流用: ML Kit 呼び出しの直列化（同時実行で SIGSEGV）、30 秒タイムアウト、長辺 2048px への縮小と
軽いコントラスト強化（1.3 倍）、画像処理は isolate で実行。グレースケール・適応 2 値化・シャープは診断書向けの調整なので入れていない。

**計測結果（忖度なし）:** 台形歪み + 7〜10° 傾きの 5 枚、および 20° 回転の 1 枚を実機で通した。

| 条件 | 補正前（1 回目） | 補正後（水平化して 2 回目） |
|---|---|---|
| 7〜10° + 台形、横書き 4 枚 | 3 枚は全項目正解。1 枚は氏名 `田中 健ニ`（カナのニ） | 4 枚とも全項目正解 |
| 20° 回転、1 枚 | 氏名 `山田 太郎B`、`Mobi le` | 氏名 `山田 太郎`、`Mobile`（末尾の `.` は抽出器で除去） |
| 縦書き 1 枚 | 傾き判定の対象外（横長の行がない） | 同左 |

ML Kit 自体が ±20° の傾きで行を落とさないので、補正の効果は「氏名の 1 文字の誤読・ごみ文字が消える」程度に留まる
（golden 26 枚中、補正前後で項目が変わったのは氏名 2 件）。残した理由は、コストが 2 回目の OCR（約 1.5 秒）だけで、
文字数が減る場合は採用しない安全側の設計になっているため。強い透視歪みは回転では直らず、1. の撮影時補正が本命。なお、傾き判定は当初「幅 > 高さ×3」で、20° では軸平行の矩形が 2:1 になって全行が落ちる不具合が
実機で見つかり、「幅 > 高さ」に修正した（`test/deskew_test.dart` に再現ケース）。

### リファクタリング

`main.dart` は画面状態とボタン処理だけになり、処理は 3 つに分かれた。

| 部品 | 役割 | テスト |
|---|---|---|
| `OcrPipeline` | 画像 → 行。直列化・タイムアウト・傾き補正・失敗ログ | 実機（プラグイン依存） |
| `extractor.dart` | 行 → 項目 | golden（24 枚）+ strict 5 本 |
| `CardStore` | golden JSON / Obsidian vault / 索引 / vCard / ログの書き出し | 一時ディレクトリで実 IO |

## 撮影ガイド（`lib/capture_screen.dart`）

**表を撮影 / 裏を撮影** は `camera` プラグインの自前カメラ画面を開く。プレビューに 91:55（名刺の実寸比）の枠を
幅 90% で重ね、枠外を暗くし、四隅を黄色で示す。上部に「名刺を枠に合わせる　影と反射を避ける　水平に」。
枠の計算は `lib/ocr/capture_guide.dart`（純 Dart、テスト済み）。ギャラリーは従来どおり長押し。

- 枠への切り抜きは**していない**。CameraX の静止画はプレビューと縦横比が違うことがあり、素朴に切ると文字が欠ける。
  ML Kit は机の背景込みでも読めている（golden 2xx）ので、ガイドは構図を揃えるためのもの。
- 初回はカメラ権限ダイアログが出る。拒否時は画面にエラー文を出すだけで落ちない。

## 建設・不動産向けの項目（`lib/ocr/extractor.dart`, `lib/ocr/address.dart`）

名刺に印刷される業界固有の番号と、利用者が付ける管理項目を分けて扱う。

| 項目 | キー | 取り方 |
|---|---|---|
| 建設業許可 | `constructionLicense` | 正規表現。`東京都知事許可（般-5）第123456号` → `東京都知事許可(般-5)第123456号`。国土交通大臣許可、特/般、全角数字に対応 |
| 宅建業免許 | `realEstateLicense` | 正規表現。`東京都知事（3）第45678号`。括弧内が回数だけなので許可行とは混ざらない |
| 法人番号 | `corpNo` | 13 桁。`T` 付きの適格請求書登録番号も同じ 13 桁として取る。電話（10〜11 桁）とは桁数で区別 |
| 資格 | `qualifications` | 1級/2級 × 建築・土木・電気工事・管工事・造園・建設機械・電気通信工事 の施工管理技士（補）、建築士、宅地建物取引士、技術士、測量士など。` / ` 区切りで重複なし |
| 部門 | `division` | 利用者入力（学習語彙の対象）。連絡先では部署の前に付く |
| 区分 | `category` | プルダウン（元請 / 下請 / 協力会社 / 取引先 / 顧客 / 設計事務所 / 官公庁 / その他）+ 自由入力 |
| 関係者 | `related` | 自社側の担当など。カンマ区切り、過去の値をチップで提示 |

番号類は電話番号の規則より前に抜き出し、行から消す（`第123456号` や 13 桁が電話・FAX に化けない）。
役職語に `現場監督 / 現場代理人 / 監理技術者 / 主任技術者 / 職長` を追加。

住所は `address`（全文）を正とし、`splitAddress` で 都道府県 / 市区町村 / 町名・丁目 / 番地・号 / 建物名 / 号室・階 に分ける。
確認画面の「住所の内訳」で各区分（都道府県はプルダウン）を直すと `joinAddress` で全文に戻り、全文を直すと内訳が追従する。
分割は正規表現の近似（既知の外れ: 四日市市 → 四日市）。

ノートの frontmatter に `corp_no / construction_license / real_estate_license / qualifications / division / category /
related / town / block / building / room` を追加し、タグ `#区分_x #部門_x #資格_x #関係者_x`、本文の `[[区分_x]]` `[[関係者名]]` で
Obsidian から引ける。索引に「区分別」「関係者別」を追加。連絡先には専用欄がないのでメモ欄に 1 行ずつ
（区分 / 関係者 / 法人番号 / 建設業許可 / 宅建業免許 / 資格）入れ、部門は部署名の前に付ける。検索は区分・関係者・部門・資格も対象。

## 続けて撮影（`ScanPageState.shootMany`）

スキャン画面の空状態にある「続けて撮影（あとでまとめて確認）」は、ML Kit ドキュメントスキャナーを `pageLimit: 30` で開き、
利用者が「完了」を押すまで名刺を次々に撮れる。撮った画像は `shot_<日時>_<連番>` の名前で、フォルダ取込と同じ
`_importFiles` に流す（表面として OCR → 抽出結果で保存 → レビューキューに積み、1 枚目を表示）。確認は 1 枚ずつ、
左右の矢印で移動。Android 以外では 1 枚撮影にフォールバックする。

## 検索の対象（`lib/ocr/history.dart`）

氏名・ふりがな・会社・役職・メモに加えて、電話・携帯・メールも検索する。比較は大文字小文字・全角半角・ひらがなカタカナを
区別せず、空白とハイフンを無視するので、`0312345678` でも `1234-5678` でも `03-1234-5678` の名刺に当たる。

## 一括取込のレビューキューと vCard 出力

- フォルダアイコン（inbox 一括取込）は OCR と golden/vault 保存のあと、取り込んだ名刺を画面のキューに載せる。
  `‹ レビュー 2/5: p01_standard ›` で前後に移動し、各名刺を修正して **JSON保存** / **電話帳に登録** できる。
- 取込中は再入禁止（`_busy`）。ML Kit の同時呼び出しは FastaLife でネイティブ側の SIGSEGV を起こした前例があり、
  実機でも二重タップで 5 枚が 8 件に増える不整合が出たため。
- 連絡先アイコンは vault の全ノートを vCard 3.0（`vault/_名刺.vcf`）にまとめる（`lib/ocr/vcard_export.dart`）。
  Google コンタクトや iCloud、別端末への一括インポート用。ノートは取込日ごとに別ファイルなので、同じ人を
  2 日に分けて撮ると vCard にも 2 件入る（重複排除は未実装）。
- OCR が例外を出した画像はスキップして `log/errors.txt` に記録し、バッチは止めない。
- `v*` タグを push すると GitHub Actions がテスト後に release APK をビルドして artifact に置く
  （`.github/workflows/release.yml`、debug 鍵署名。ストア署名は手元のみ）。

## Obsidian ノート出力（`<外部領域>/vault/`）

保存のたびに `_名刺一覧.md`（`lib/ocr/vault_index.dart`）も再生成する: 全名刺の表（氏名 / 会社 / 職種 / 地域 / 取込日）と
**会社別・職種別・地域別**の人数と人名リンク。各ノートの frontmatter だけを読んで集計するので、Obsidian 側で
ノートを手直ししても次回保存時に反映される。

保存のたびに golden JSON と同じ項目から Obsidian 形式の MD を 1 枚 1 ファイルで書く
（`lib/ocr/card_note.dart`）。FastaLife の vault パーサ（`ObsidianEngine`）がそのまま読める方言に合わせた:

- frontmatter はフラットな `key: value` のみ（`name` `kana` `roman` `company` `dept` `title` `job`
  `phone` `mobile` `fax` `email` `url` `postal` `pref` `city` `address` `scanned` `vertical` `source`）。
- `tags: [a, b]` を 1 行で。ネストタグ `#a/b` は FastaLife 側が `/` を読めないので `_` 区切り:
  `#会社_サンライズ #職種_営業 #役職_部長 #部署_営業部 #地域_東京都 #市区_渋谷区 #市外局番_03 #ドメイン_sunrise_co_jp #取込_2026-10`。
  縦書き名刺には `#縦書き` が付くので、要確認ノートをタグで絞り込める。
- `[[会社名]]` `[[都道府県]]` `[[職種_○○]]` をリンクにして、バックリンク／グラフで「同じ会社の人」「同じ県の人」
  「同じ職種」が辿れる。
- 職種（`job`）は部署・役職語からの 13 分類（営業 / 販売 / 技術開発 / 経営 / 製造 / 管理 / マーケティング / 企画 /
  デザイン / コンサルティング / 研究 / 調達 / 医療）。実名刺で外れた語を見てから表を増やす。
- ファイル名は `<氏名>_<yyyy-mm-dd>.md`（FastaLife と同じ禁止文字セットで `_` 置換）。

FastaLife の OCR から流用したもの: 全角→半角と `1O2`→`102` / `1l2`→`112` の数字誤読補正（`blood_test_parser_extraction.dart` の
`_normalizeOcrText` 相当）、OCR → 表 → vault ノート → グラフ登録というパイプライン構成。ML Kit のネイティブ呼び出しを
直列化する `OcrService` の排他制御は、本スパイクが 1 枚ずつしか処理しないため未導入（連写モードを入れる時に必要）。

## 計測（2026-10-24、P08 T / Android 16、合成名刺 5 種 × クリーン描画 + 写真風劣化）

写真風劣化 = 机の背景に置いて台形歪み・ガウスぼかし・ノイズ・影のグラデーション・±3° 回転・2/3 縮小・JPEG。

| 項目 | 全 13 枚 | 縦書きを除く 11 枚 | 備考 |
|---|---|---|---|
| name | 13/13 | 11/11 | 「最大文字高さの CJK 行 = 氏名」が全レイアウトで成立 |
| phone / mobile / fax | 100 % | 100 % | `FAX: 019-62 3-1235` の数字内空白、`ー`→`-` を補正 |
| email / url | 100 % | 100 % | `taro. yamada@sunr ise. co. jp` の空白、`@`→`ê` 誤読を補正 |
| company | 12/13 | 11/11 | 外れは縦書きの文字誤読（`印刷`→`印選`） |
| dept / title | 100 % / 12/13 | 100 % | `開発本部シニアエンジニア` の無空白連結を部署接尾辞で分割 |
| postal / address | 11/13 | 11/11 | 外れは縦書き 2 枚（`〒980-0811` が `〒のo01081ー`） |

- リリース APK（日本語モデル同梱、R8 有効）: **77.0 MB**。デバッグ APK は 197 MB。
- リリースビルドには `android/app/proguard-rules.pro` の `-dontwarn com.google.mlkit.vision.text.(chinese|devanagari|korean).**`
  が必須。プラグインが全スクリプトのクラスを参照しているため、無いと `minifyReleaseWithR8` が落ちる。

### 分かったこと（忖度なし）

- **Android は `implementation("com.google.mlkit:text-recognition-japanese:16.0.1")` が必須。**
  プラグインは `compileOnly` 宣言のみで、無いと `NoClassDefFoundError: JapaneseTextRecognizerOptions`
  で即クラッシュする。出回っているサンプルコードはこれを書いていない。
- **縦書きは ML Kit の構造的弱点。** 縦 1 列が 1 行として返り、数字列はほぼ破壊される。
  90 度回転しても文字が横倒しになるだけで改善しない。`isVertical` で検出して「要手動確認」と
  出すのが現実的な対処で、精度を上げる手段は端末内 LLM か別エンジンしかない。
- 合成描画は実写より易しい。写真風劣化でも数字・メールは補正で 100% に戻せたが、
  実写では紙の反射・手ブレ・小さすぎる文字で OCR 行そのものが欠ける。判定基準は実名刺 30 枚に対して適用する。
- ローマ字名に `Takahash i` のような単語内空白が残る（補正未実装。氏名は目視修正前提なので放置）。
